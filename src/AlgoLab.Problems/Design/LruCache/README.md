# LRU-кеш

Нужно спроектировать кеш фиксированной ёмкости с двумя операциями: `Get(key)`
возвращает значение по ключу или -1, если ключа нет, и одновременно отмечает
ключ как недавно использованный; `Put(key, value)` кладёт или обновляет пару
ключ-значение, тоже отмечая ключ как недавно использованный. Когда при
вставке нового ключа ёмкость кеша исчерпана, вытесняется тот ключ, который
дольше всех не использовался (least recently used).

В этом тренажёре задача — на проверку самого движка: вход не одно значение, а
последовательность операций `Get`/`Put`, а выход — последовательность
результатов `Get` (для `Put` результата нет, поэтому на этой позиции стоит
`null`).

Источник: [LeetCode 146. LRU Cache](https://leetcode.com/problems/lru-cache/)

## Разбор

**Словарь плюс двусвязный список.** Нужны две вещи одновременно: быстрый
доступ по ключу и быстрое обновление порядка «давности» использования.
Словарь `key → (value, узел списка)` даёт доступ по ключу за O(1).
Двусвязный список хранит ключи в порядке использования — от самого свежего
у головы до самого давнего у хвоста. `Get` и успешный `Put` по существующему
ключу переносят узел этого ключа в голову списка (O(1) на операцию списка,
потому что для переноса узла на голову не нужно искать его позицию — она уже
есть в словаре). Когда `Put` на новый ключ заполняет кеш до ёмкости, из
хвоста списка удаляется самый давний ключ, и по нему же чистится словарь.
Каждая операция — O(1), а n здесь считает не размер структуры, а число
операций во входной последовательности, поэтому суммарное время на n
операций — O(n). Память ограничена ёмкостью кеша и от числа операций не
растёт, но поскольку n — это число операций, а не размер данных, декларация
сложности по памяти здесь тоже O(n): каждая операция добавляет свою запись в
массив результатов.
