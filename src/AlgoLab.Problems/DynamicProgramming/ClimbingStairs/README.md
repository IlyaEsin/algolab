# Подъём по лестнице

Нужно подняться по лестнице из `n` ступеней, за один шаг поднимаясь либо на
1, либо на 2 ступени. Сколько существует различных последовательностей шагов,
которыми можно подняться на самый верх?

Источник: [LeetCode 70. Climbing Stairs](https://leetcode.com/problems/climbing-stairs/)

## Разбор

Последний шаг к ступени `n` — это либо шаг на 1 со ступени `n-1`, либо шаг на
2 со ступени `n-2`. Значит, число способов добраться до `n` — это сумма
способов добраться до `n-1` и до `n-2`: `ways(n) = ways(n-1) + ways(n-2)`.
Это рекуррентность Фибоначчи со стартовыми значениями `ways(1) = 1` и
`ways(2) = 2`.

**Два счётчика.** Раз для вычисления `ways(n)` нужны только два предыдущих
значения, не обязательно хранить всю последовательность — достаточно катить
вперёд пару переменных. Один проход от 2 до `n`, O(n) по времени, O(1) по
памяти.

**Рекурсия с мемоизацией.** Та же рекуррентность, записанная напрямую как
рекурсивная функция, — но без кеша она пересчитывала бы каждое поддерево
экспоненциально много раз. Словарь «ступень → уже вычисленный ответ»
устраняет повторные вычисления: каждое значение `ways(k)` считается один раз,
поэтому по времени всё ещё O(n), а по памяти — O(n) на кеш и стек вызовов.

## Почему у этой задачи нет кривой роста

У этой задачи в тренажёре нет измерения — она не отвечает на запрос кривой
роста, и это осознанный выбор, а не недосмотр. Ответ (число способов) растёт
как числа Фибоначчи и уже примерно на 90 ступенях перестаёт помещаться в
`long`: дальше расширять вход попросту некуда, не переписывая задачу на
длинную арифметику, которая тут ни при чём — суть задачи в самой
рекуррентности, а не в работе с большими числами. А раз вход нельзя вырастить
за пределы полусотни-сотни ступеней, а лестница измерения стартует с 64 и
дальше только удваивается, честной кривой всё равно не получится: почти вся
лестница легла бы на один и тот же, уже не растущий вход.
